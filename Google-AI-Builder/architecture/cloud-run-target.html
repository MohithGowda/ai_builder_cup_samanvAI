PROPOSED TARGET / 03

Independently deployable. Deliberately connected.

A migration target for SamanvAI: independently released React microfrontends and FastAPI services, with GitLab CI building and deploying containers to Google Cloud Run.

ARCHITECTURE STATUS
Proposed, not deployed
Cloud Run is not Kubernetes. This target uses managed Cloud Run services. It does not deploy into a Kubernetes cluster. If Kubernetes is a firm requirement, use GKE and a separate deployment target rather than mixing the two models.

03.1 / PLATFORM VIEW

From GitLab commit to a scoped service response.

Current delivery: GitLab builds one image containing the Vite frontend and FastAPI backend and deploys one Cloud Run service. The multi-service and microfrontend boundaries below are the proposed migration target, not deployed infrastructure.

03.2 / IMPLEMENTATION NOTES

Keep the boundaries honest.

Microfrontend release units

Start with a shared shell and independently built citizen and official remotes. Define versioned UI contracts and an explicit compatibility policy. A static Cloud Run container can serve each bundle; avoid loading arbitrary remote code without trusted origins and CSP.

Split by data ownership

Extract applications first, then governance read models and agent/knowledge access. Services communicate through APIs or domain events. Use an outbox for reliable publication; avoid direct access to another service's tables. A shared Cloud SQL instance is a migration step, not shared ownership.

GitLab deploy identity

Use GitLab OIDC with Google Workload Identity Federation, narrowly bound to the project and protected branch. Grant Artifact Registry writer and Cloud Run deploy permissions to the pipeline identity. Runtime service accounts get only their own data, Pub/Sub and Vertex permissions.

Migration order: add health/readiness contracts and external PostgreSQL; extract the cases API behind the existing client; move governance reads to a projection; isolate agent calls; then split the shell and remotes. Deploy each step behind a stable gateway route and retain a rollback revision. Do not split the six LangGraph nodes into six services by default.
